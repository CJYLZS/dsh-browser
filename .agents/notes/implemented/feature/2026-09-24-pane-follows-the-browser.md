# Agent Note: 面板跟着浏览器走：谁起浏览器、谁关浏览器

Status: implemented

## Problem

浏览器属于会话，面板只是它的观察窗，但两边的生命周期一直是各走各的，于是同一个缺陷从两头冒出来：

- **agent 起了浏览器，人看不见。** 没有打开面板的会话里，工具照样把页面驱动起来，结果只有几行文本回报（"Clicked link …"、"Typed … into …"）和一张截图；用户想要的是看着它发生，却得自己想到去点「新标签页 → 浏览器」。
- **用户关了浏览器，它自己回来。** 面板上的「关闭浏览器」把浏览器停下，但 viewer 仍订阅着，而实例留在 pool 里；`addViewer()` 在订阅数 0→1 时走 `openStreamForViewers()` → `ensure()`，`ensure()` 见状态不是 `ready` 就重新起一台——于是切到别的侧栏标签再切回来、收起再展开栏目、客户端 HMR 重载，任何一次**重新订阅**都会起一台停在 `about:blank` 的新浏览器（用户报告："关闭之后没过一会浏览器会自动打开回到空白页"）。2026-09-24 用假启动器把这个机制钉成了用例（见下）。
- 附带的两处身份不一致：侧栏标签芯片没有字形（芯片画的是注册表在打开时抓的标题文字，本插件没注册标题组件），guide 卡片画的是默认立方体（条目没给 `icon`）。

## Decision

1. **"用户关的"和"它死了"分开。** 新增 `SessionBrowser.stop()`：置 `userClosed` 再走 `close()`，这是面板关闭按钮的入口（viewer 的 `close` verb → `stop()`）。`close()` 仍是"停掉"——配置变更、会话销毁、启动失败。viewer 路径（`openStreamForViewers()`）见 `userClosed` 直接返回；`ensure()` 在开头清掉它，因为够到 `ensure()` 的每一条路径（工具、restart、改启动项）都是**在要一台浏览器**。
2. **关闭浏览器同时关闭它的面板标签。** 面板 body 通过 seat 注入的 `useTabInfo` 拿到 `tab.actions.close()`，在发出 `close` 之后调用。留下的观察窗没有东西可看，却是下一个可能把浏览器叫回来的订阅者。
3. **agent 起浏览器时面板自己打开。** 客户端半边 `revealOnBrowserStart()`（[`src/client/reveal.ts`](../../../../src/client/reveal.ts)）在"侧栏没有浏览器标签"时每 1.5 s 读一次 `/dsh-browser/status`，当前会话的实例从"没在跑"（含从未出现过）变成"在跑"就 `ctx.sidebarRight.openTabIn(sessionId, 'cdpBrowser')`——`openTabIn` 会在同一步展开栏目，所以侧边栏自己就开了，并且已经在那一页上。判据是**变化**而不是状态：用户手动关掉的观察窗不会因为浏览器已经在跑而被重新拉出来。
4. **浏览器只有一个字形。** [`src/client/glyph.ts`](../../../../src/client/glyph.ts) 只做转出：侧栏标签标题（`title.tsx` 注册进 `sidebar.right.pane.tab.title`）与 guide 条目（`definition.ts` 的 `guide[].icon`）用产品自带的 `IconGlobeOutlineRegular`——harness 内置的 Browser 标签画的正是它，自己再画一个地球就会在一行标签里出现两个略有差别的地球；地址栏的 globe 用同一图标的 `Medium` 权重，与它旁边的锁同粗细。`definition.ts` 把字形作为**入参**收下而不是 import 它，这样 `test/*.test.ts` 才能在 Node 的类型剥离下 import 那份定义（primitives 包的 CSS module 在那里加载不了）。

## 为什么"变化"而不是"在跑"

触发条件如果只是"这个会话有浏览器在跑，而标签没开"，就会把用户**主动关掉的观察窗**在下一次工具调用时重新拉出来——那是用户的决定，不该被覆盖。只看变化则两种意图都成立：用户关掉后，浏览器停止（状态 `closed`），下一次工具调用让它 `starting`——这是一次变化，面板回来是对的；而浏览器一直在跑、用户只是关掉面板，状态始终 `ready`，没有任何变化，面板就保持关闭。

代价写在 `justStarted` 的注释里：客户端**首次**读到某个会话"在跑"时也算变化（例如长回合中刷新页面），面板会打开。反过来的取舍（要求先看到"没在跑"才算）会漏掉最常见的一次——工具调用在两次轮询之间就完成了，客户端第一次看到它时已经是 `ready`。

## Alternatives considered

**让 viewer 重连理解为"要一台浏览器"（保持原状）**：这正是缺陷本身。崩掉的浏览器需要下一次请求把它带回来，但"面板重新挂载"不是一次请求。

**关掉浏览器、保留标签，只显示"已关闭 + 重开"**：观察窗留下了，但标签与浏览器状态长期不一致，而且每次重新订阅都要判断"这次该不该复活"，规则比"关了就关"复杂。改用 `stop()` 后，重开浏览器有一个明确入口：下一次工具调用。

**用 SSE 或长轮询把状态推给客户端**：更干净，但本插件必须自己再加一条流（viewer socket 只在面板打开后存在，恰好是这件事的反面）。1.5 s 一次的本地 GET 只在"侧栏没有浏览器标签"时发生，代价更低；真嫌它难看再换。

**把轮询改成订阅会话的工具调用流**：客户端能看到工具调用，但要读会话/对话装配的内部结构，而那是本插件没有稳定契约的层；状态路由是插件自己的，语义也正好是"谁在跑"。

**设置页导航的图标也统一成地球**：做不到。设置外壳按 section id 硬编码图标（harness 的 `SettingsRoot.tsx` 的 `navIcon`，未知 id 一律齿轮），`settings.section` 的注册项只有 `id`/`order`/`label`，没有 icon 字段；外部插件没有表达自己字形的途径。记为已知不一致，要改得动 harness。

## Consequences

- 「关闭浏览器」= 结束这一次观察：浏览器与标签一起消失；下一次需要浏览器的工具调用会新起一台，面板跟着回来（这两个决定在同一轮里才自洽）。
- 客户端多一个 1.5 s 的本地轮询，只在侧栏没有浏览器标签时进行；面板打开时不发请求。
- 侧栏标签芯片与 guide 卡片现在有地球字形；设置页导航仍是齿轮。
- 验证：`test/session-browser.test.ts` 两条新用例（"viewer 重连不复活用户关掉的浏览器"、"工具调用会新起一台"）——把 `openStreamForViewers()` 的 `userClosed` 判断临时去掉后**实测红一条**，恢复后全绿；`test/client-surface.test.ts` 钉住 `justStarted` 的判定与 guide 条目的字形。
