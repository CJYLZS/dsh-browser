# Agent Note: 设置页能说出是谁、也能关掉它

Status: implemented

## Problem

设置页的横幅里折着一行实例明细，每行是 `会话 0599913e · running`。这一行有两个问题，而且都不是排版问题：

1. **它不说是谁。** 标签来自 `instanceLine` 把 `sessionId` 去掉 `session-` 前缀再截前 8 位（[settings-layout.ts](../../../../src/client/settings-layout.ts)）。每个会话 id 都以 `session-` 开头，所以截出来的八位十六进制对所有行都一样长、一样陌生；用户看着三行不知道哪一行是自己正在用的对话。宿主其实**有**可读的名字（会话标题），只是这条路没走到设置页。
2. **它关不掉。** 那一块是只读文本。用户想停掉一个浏览器，只能去侧栏找到它的标签页，一个个关页面——而"关掉最后一个页面"被解释成"停掉浏览器"，所以这个动作对用户来说是隐式的、且有副作用。

工作区共享 profile 落地之后这一块会更糟：一个工作区只应有一个浏览器，用户看到三行"会话"会以为泄漏。但**这不需要等**——它修的是今天就在的问题。

## Decision

三件事一起改，各自独立可验证：

**报告带上标题。** `BrowserStatus` 增加可选 `title`。解析在 [labels.ts](../../../../src/view/labels.ts) 的 `SessionLabels`，三个来源按顺序问：

1. `ctx.sessionQuery.readTitle()`——活会话与冷日志都答。这一点要紧：**浏览器还在跑的会话，不一定是本进程打开的会话**，只问活会话会在最需要名字的地方失败。
2. `ctx.sessionTitle.get()` 配 `ctx.sessions.get()`——活会话自己的日志折叠。
3. 都没有就是没有，页面显示"未命名会话"。

三个服务都是**可选**的（用 [serviceOf](../../../../src/tools/spill.ts) 结构化查找），一个装配都不挂时设置页显示回退标签，而不是路由失败。

**缓存 5 秒。** 路由是 1.5 秒轮询的（侧栏对账），而读标题意味着折叠一个会话的日志。标题是持久状态，只在用户改名或 provider 产出时变，几秒的陈旧不可见；每次轮询每个浏览器折一次日志则不是。**读失败不进缓存**（那是可能下一次就好的服务），**"没有标题"进缓存**（那是"这个对话还没说过话"，会稳定一阵）。

**行尾一个「关闭浏览器」，与会话一一对应。** `POST /dsh-browser/pages` 的 `close` 多认一个 `all: true`：不带 targetId，意思是"这个会话不要浏览器了"。宿主侧走 `pool.dispose(sessionId)`——浏览器关掉、实例遗忘，行随之消失。不留"已关闭"占位，因为这一块列的是**现在谁在用浏览器**，不是历史。

客户端只发"这个会话不要了"，不必知道宿主怎么实现；`workspace` 模式落地后同一个请求会变成"从共享实例上摘除这个会话、计数减一"，而客户端不用改。

**旁观不再能创建浏览器。** 这条是让「关闭」留住的关键：viewer 连进来时走 `pool.peek` 而不是 `pool.get`，没有浏览器就报 `has no browser to watch` 并关闭 socket。否则一个还挂着的面板、一次切回标签页、一次客户端重载，都会在 1.5 秒内把用户刚关掉的浏览器重新拉起来。

配套的一半在客户端：**入口面板先等自己的 `openPage` 答完再连 socket**。原先两者并发，浏览器启动要几秒，socket 先到就找不到浏览器——那本来是被 `pool.get` 掩盖的竞态。现在次序是显式的：问页（会启动浏览器）→ 答完 → 连上去看。

## Testing

- `test/view-labels.test.ts`：三个来源的顺序、冷会话也能命名、一个服务都没挂时不抛、失败重试而空标题缓存、TTL 与改名。
- `test/settings-layout.test.ts`：行以标题开头、无标题时是"未命名会话"且**不含** `session-` 或那八位十六进制、空白标题算没有标题。
- `test/view-pages.test.ts`：`all: true` 停掉浏览器并从报告消失、本来就没有浏览器时答 ok、关掉之后 viewer 连不上、`all: false` 不算。
- `test/view-server.test.ts`：**看着一个没有浏览器的会话不会起浏览器**。
- `test/client-api.test.ts`：关闭请求的报文形状与拒绝时抛错。

## Alternatives considered

**把 id 显示得更完整（`会话 0599913e-…`）。** 更长的十六进制仍然不是名字，只是更难读的十六进制。用户要的是"哪个对话"，不是"哪串字节"。

**让设置页自己去查标题（客户端拉会话列表）。** 客户端半边注入的是 `slots`/`locale`/`sidebarRightTabs`，没有 `sessions` 服务；而冷会话的标题只有宿主能读（日志在磁盘上）。标题属于报告，因为报告已经知道有哪些实例。

**用 `ctx.sessions.list()` 一次读全部标题。** 只覆盖活会话，正好漏掉浏览器比视图活得久的那一半。`sessionQuery` 是为这个场景存在的。

**关闭按钮做成"关掉这台浏览器"（面向进程）。** 用户手里的是会话行，不是进程列表；`workspace` 模式下"关掉这台浏览器"会连别人的页面一起关。按钮必须落在会话上，进程去留由引用计数决定。

**关掉后保留一行灰色的"已关闭"。** 这一块回答的是"现在谁在用浏览器"。留占位会让人以为还有一个实例，而失败原因由下一个真正需要浏览器的请求重新报出来更准确。

**viewer 仍然 `pool.get`，靠 `userClosed` 挡住重开。** 已经存在的机制，但它只挡"用户从面板关的"这一条路径：设置页关闭走的是另一条，`userClosed` 不会为它置位。让旁观**根本不创建**是更简单的不变量——一条规则，两个入口都自动正确。

## Consequences

- **一个已连接的 viewer 在浏览器被关掉之后，看到的是"没有可看的浏览器"而不是自动恢复。** 这是有意的：旁观是观察者不是所有者。要重新开，用工具或入口点一次。
- **标题读不到时会显示"未命名会话"。** 一个没挂 `session-title` 的装配就是这样；这不是错误，但用户看到的是回退标签。
- **`all: true` 与 `temp`/`session` 模式的旧语义一致**（一个会话一个浏览器，关掉就是关掉），所以这一步不改变现有模式的任何行为。它是 `workspace` 模式的前置：那时"关掉会话的浏览器"会变成"摘除这个会话、计数减一"，而路由与客户端都不用动。
- **`pool.dispose` 现在承担两件事**：会话销毁时的回收，和用户显式关闭。两者都应当遗忘实例，所以共用一条路径是准确的；等引用计数落地时它会变成"减一，归零才关"。
